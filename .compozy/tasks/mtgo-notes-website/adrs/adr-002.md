# ADR-002: Private R2 plus a Pages Function for the Windows download

## Status

Accepted

## Date

2026-08-17

## Context

The WinUI zip will exceed the Cloudflare Pages **25 MiB** per-file limit, so it cannot live in `dist`. The PRD requires a Cloudflare URL as the primary CTA, a stable `latest` object, a versioned archive object, an empty state when nothing is published, and GitHub Releases as the CI archive only.

A public R2 URL is simpler but turns a missing object into a raw 404 and exposes storage URLs. A standalone Worker is cleaner if we leave Pages later, but it is a second project for V1.

## Decision

Store zips in a **private** R2 Standard bucket `mtgo-notes-releases`. Serve them through **Pages Functions** in `web/functions`:

| Route | File | Behavior |
|---|---|---|
| `GET /download/windows` | `functions/download/windows.ts` | Stream `releases/windows/latest.zip`. Set `Content-Disposition` from `latest.json` when present. If the zip is missing, **302** to `/download?available=0`. |
| `GET /download/status` | `functions/download/status.ts` | Always **200** JSON `ReleaseStatus`. |

R2 keys:

- `releases/windows/MTGONotes-<version>-win-x64.zip`
- `releases/windows/latest.zip`
- `releases/windows/latest.json`

Binding name: `RELEASES`.

`.github/workflows/release.yml` uploads all three objects only on successful `v*` tag builds, after the GitHub Release is created. `workflow_dispatch` drafts must not overwrite `latest`. An R2 failure fails the job.

The Function streams the object body (does not presign, does not 302 to R2). Cache header: `private, no-store`.

## Alternatives Considered

### Alternative 1: Public R2 + static latest URL

- **Description**: Public bucket; CTA is the object URL.
- **Pros**: No Function.
- **Cons**: Missing object is a raw 404; weaker header control; empty state is harder.
- **Why rejected**: The PRD forbids a dead link / 404 as the visitor outcome.

### Alternative 2: Standalone Worker

- **Description**: Separate Worker in front of the same bucket.
- **Pros**: Survives a Pages → Workers site migration cleanly.
- **Cons**: Second Cloudflare project and route for V1.
- **Why rejected**: The site already lives on Pages; a colocated Function is enough.

### Alternative 3: Presigned GET from the Function

- **Description**: Function mints a short-lived R2 URL.
- **Pros**: Function does not stream large bytes.
- **Cons**: Extra moving parts for a public free zip; visitor leaves the first-party path.
- **Why rejected**: Streaming through the Function keeps the CTA on `/download/windows`.

## Consequences

### Positive

- Zip never sits in Pages assets.
- Same-origin CTA and status endpoint.
- Empty state works with or without JavaScript (`?available=0`).

### Negative

- Large zips stream through the Function. Acceptable for V1 volume.

### Risks

- Status JSON and zip can drift if CI writes one key and not the others. CI must write versioned zip, `latest.zip`, then `latest.json`, and fail the job if any put fails.
- Versioned-only objects without `latest` must present as unavailable.

## Implementation Notes

- Do not bind or document a public bucket custom domain.
- Local: `wrangler pages dev dist` with the `RELEASES` binding; tests mock `R2Bucket`.
- Required GitHub secrets: `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` with R2 edit on `mtgo-notes-releases`.
