# ADR-001: Static Astro in `web/` on Cloudflare Pages

## Status

Accepted

## Date

2026-08-17

## Context

Issue #21 requires a brochure site with preview + production hosting, no auth or CMS, and a first-party download that is *not* a Pages static asset. The repository is a WinUI / .NET companion; there is no existing web app. Cloudflare now steers new projects toward Workers + Assets, and `@astrojs/cloudflare` v13+ dropped Pages SSR. This site does not need SSR.

The existing brand artwork lives at `__oldversion__/assets/icons/mtgo-notes-transparent.png` and `mtgo-notes.ico`. The site must use that icon as the favicon and in chrome.

## Decision

Ship a **static Astro** site in **`web/`** of this repository.

- Default Astro static output to `web/dist`. No `@astrojs/cloudflare` adapter.
- Cloudflare Pages Git integration uses root directory `web`, build `npm ci && npm run build`, output `dist`.
- Pages project name: `mtgo-notes` (`mtgo-notes.pages.dev` until a custom domain exists).
- Copy the brand PNG and ICO into `web/public/brand/` and `web/public/favicon.ico` so the frozen `__oldversion__/` tree is not a build dependency.
- Inter is the shipped typeface (ADR-004). `DESIGN.md` color, type scale, spacing, and component tokens still apply.

## Alternatives Considered

### Alternative 1: Sibling `mtgo-notes-web` repository

- **Description**: Separate repo and Pages project.
- **Pros**: Isolates site CI from the Windows build.
- **Cons**: Two repos; release publish and site copy drift; `CONTEXT.md` / `DESIGN.md` live elsewhere.
- **Why rejected**: The download pipeline already belongs to this repo’s `release.yml`.

### Alternative 2: Host the site on Workers + Assets

- **Description**: Follow Cloudflare’s current default for new Astro apps.
- **Pros**: Future-proof against Pages freeze; one compute product.
- **Cons**: Diverges from the PRD host line; extra migration with no V1 feature gain for a static brochure.
- **Why rejected**: The PRD named Pages. Static Astro on Pages still works. Revisit if Pages is retired.

### Alternative 3: Hand-rolled HTML or another SSG

- **Description**: No Astro.
- **Pros**: Fewer dependencies.
- **Cons**: More layout work against `DESIGN.md`; weaker MD/component split for five routes.
- **Why rejected**: Astro matches a content brochure and was chosen during design grilling.

## Consequences

### Positive

- Site, copy, design tokens, and release publish live in one repository.
- No SSR adapter, so the Astro 6 Pages-drop does not apply.

### Negative

- A .NET repo now carries a Node workspace. Pages builds only `web/`; Windows jobs ignore it.

### Risks

- Accidental inclusion of the zip in `web/public` or `dist`. Tests must forbid binary artifacts in the site output.

## Implementation Notes

- `web/package.json` is a standalone workspace. Do not add it to the .NET solution.
- Header `BrandMark` renders ` /brand/icon.png` next to the wordmark. `<link rel="icon">` points at `/favicon.ico`; also emit an SVG/PNG apple-touch icon from the same PNG.
