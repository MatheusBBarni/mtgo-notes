# ADR-009: Read Live Match Context Through a Read-Only MTGOSDK Attach

## Status

Accepted

## Date

2026-08-17

## Context

ADR-002 and ADR-005 forbade inspecting the MTGO process, memory, files, logs, or traffic. Detection today is UIA plus cropped OCR on a user-selected visible window.

That boundary cannot deliver reliable opponent, format, and phase signals. The user accepted the account-policy risk in exchange for Videre-quality live context plus the existing notes product.

MTGOSDK attaches to an already-running MTGO process with ClrMD, exposes typed objects, and does not modify MTGO code. It can also log on and write back through UI events. Those write paths are out of scope.

## Decision

Use MTGOSDK as the primary live context source.

- Attach only to an MTGO process the player already launched and logged into. Never call `Client.LogOn`, never store MTGO credentials, never send chat, never queue, concede, or otherwise drive the client.
- Subscribe to play objects only far enough to emit the existing evidence fields: `opponent`, `phase`, `format`, `game`, `result`. Persist `User.Id` as a stable alias key when present.
- Map match state onto the current internal phases:
  - pairings / match not started → `pre_match`
  - `CurrentGame` live → `in_game_restricted`
  - between games / sideboarding (`CurrentGame == null` while match active) → `between_games`
  - match finished → `completion_pending` until the player confirms
  - missing, conflicting, or disconnected state → stay or enter `in_game_restricted`
- Player confirmation is still required before a detected opponent becomes persistent history.
- Do not subscribe to zone, card, stack, life, collection, or trade APIs in this rewrite. Those APIs exist; using them turns the product into Videre Tracker.
- Keep UIA/OCR as a degraded fallback when MTGO is an unsupported build, attach fails, or the player disables live attach. Manual entry remains the last resort.
- Live attach is an explicit, versioned consent separate from public-deck lookup. It can be paused and revoked immediately. Pausing fails the overlay closed.

This supersedes ADR-002's "no process inspection" rule and ADR-005's "UIA/OCR is the V1 provider" rule. Tournament-conservative disclosure (ADR-001) is unchanged.

## Alternatives Considered

### Alternative 1: Keep UIA/OCR as the only automatic source

- **Description**: Continue the current detector.
- **Pros**: Stays inside the original policy boundary.
- **Cons**: Fragile against MTGO UI changes; cannot meet the requested Videre-like context.
- **Why rejected**: The rewrite exists to replace this as the primary source.

### Alternative 2: Full Games API / Tracker clone

- **Description**: Log every zone change, life total, and collection delta.
- **Pros**: Matches videreproject.com's tracker.
- **Cons**: Competes with Tracker, explodes scope, and pressures in-game disclosure.
- **Why rejected**: The differentiator is opponent memory, not another game logger.

### Alternative 3: Official or MTGBot live API only

- **Description**: Wait for a documented Daybreak or MTGBot feed.
- **Pros**: Cleaner authorization story.
- **Cons**: No such general API exists for non-streamers.
- **Why rejected**: Same reason ADR-005 rejected waiting; the chosen source is now MTGOSDK instead of UIA.

## Consequences

### Positive

- Opponent, format, and phase become event-driven instead of OCR guesses.
- `User.Id` gives the notebook a stable identity key OCR never had.
- Fallback detectors remain, so a Thursday MTGO patch does not brick notes.

### Negative

- Daybreak can treat process attach as an EULA violation and suspend accounts. The product must disclose this during onboarding and must not claim official approval or tournament safety.
- MTGOSDK is live-at-head. Bindings break when MTGO updates. The app must detect version mismatch and fall back.
- Richer live state makes historical leak bugs more tempting. Disclosure stays the only publisher of overlay views.

### Risks

- **Policy change**: Daybreak enforcement is outside our control. Disable and uninstall must be obvious.
- **Version skew**: pin MTGOSDK, record the supported MTGO version, and fail closed to UIA/OCR/manual on mismatch.
- **Reconnect**: MTGO crashes must dispose the client, re-attach, and resume without duplicating encounters.
- **Self vs opponent**: the current user must never become the opponent candidate.

## Implementation Notes

`MTGONotes.Live` implements the same `IContextSource` as the UIA/OCR adapters. The encounter reducer must not know which adapter produced a field. See [the rewrite plan](../_plan.md).

This is not legal advice. Onboarding copy must say the attach reads the local MTGO process, is unofficial, and can be turned off.
