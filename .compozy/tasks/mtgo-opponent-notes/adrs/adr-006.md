# ADR-006: Encrypt the Live Notebook with SQLCipher and DPAPI

## Status

Accepted

## Date

2026-07-28

## Context

The notebook contains private observations and public lookup history. ADR-003 requires local SQLite, encrypted portable backup, safe merge/replace restore, and one-way plaintext export. Plain SQLite protected only by profile permissions leaves a copied database readable. Requiring a password at every launch would add friction to a match companion.

## Decision

Use a Rust-owned SQLCipher database and protect its key with Windows Data Protection API.

- Generate a random 256-bit database key on first launch. Seal it with current-user DPAPI and store only the sealed blob beside the database.
- Open SQLCipher with the raw key before the first database read. Verify cipher activation and schema compatibility before migrations.
- Keep all SQL and transactions in the Rust repository. Enable foreign keys, WAL mode, a bounded busy timeout, and versioned forward-only migrations.
- Use opaque UUIDv7 identifiers and UTC millisecond timestamps. Store encounter transitions, merges, deletions, classifications, and restore operations as auditable records.
- Implement search with SQLCipher-backed SQLite FTS5 tables maintained transactionally from non-deleted records.
- Create portable `.mtgonotes` backups as an authenticated, passphrase-encrypted streaming archive. The encrypted payload contains a versioned manifest, canonical logical records, classifier provenance, and integrity hashes; plaintext backup data is never written to disk.
- Restore decrypts and validates into a temporary SQLCipher staging database. Merge runs idempotent identity-aware transactions. Replace builds a complete replacement database and swaps it atomically only after validation. Both retain a rollback snapshot until the user confirms success.
- Plaintext `.txt` export streams only the requested scope to a temporary sibling file, flushes it, then atomically renames it after the unencrypted-data warning is accepted.

## Alternatives Considered

### Alternative 1: Plain SQLite with Windows ACLs

- **Description**: Rely on the current user's profile permissions and recommend BitLocker.
- **Pros**: Uses standard SQLite and Tauri's generic SQL plugin.
- **Cons**: A copied database is readable when full-disk encryption is absent or bypassed.
- **Why rejected**: Private notebook content merits application-layer at-rest encryption without daily password friction.

### Alternative 2: User Passphrase for the Live Database

- **Description**: Derive the live database key from a passphrase entered at launch.
- **Pros**: Portable user-controlled secret and strong separation from the Windows account.
- **Cons**: Daily friction, no recovery, and a poor fit for rapid match use.
- **Why rejected**: DPAPI provides the selected Windows-user boundary while portable backups remain passphrase controlled.

### Alternative 3: Raw Database File as Backup

- **Description**: Copy the encrypted SQLCipher database and its DPAPI-wrapped key.
- **Pros**: Simple and fast.
- **Cons**: The DPAPI key is machine/user bound, raw copies are not portable, and merge restore is difficult.
- **Why rejected**: A canonical logical archive supports portable, version-aware merge and replace restore.

## Consequences

### Positive

- Copied live database files are not readable without the Windows-user-protected key.
- Users do not enter a password during normal launch.
- Backup is portable and independent from the device-bound live key.
- Staging and atomic swaps prevent partial restore states.

### Negative

- SQLCipher native packaging and migrations require dedicated Windows tests.
- Loss of the Windows profile can make the live database inaccessible without a portable backup.
- Logical backup and merge restore are more complex than copying a database file.

### Risks

- **Key loss**: Encourage first backup after onboarding and never overwrite the sealed key non-atomically.
- **Migration failure**: Back up the encrypted live database before migration and restore it automatically on failure.
- **Concurrent destructive operations**: Serialize backup, restore, export, purge, and migration through an operation coordinator.
- **Temporary plaintext**: Prohibit plaintext staging and test temp-directory scans after interrupted operations.

## Implementation Notes

Use SQLCipher's raw-key mode and confirm `cipher_status` after the first validation read. Zero key buffers after use where supported. Set file ACLs to the current user even though the contents are encrypted. The portable archive uses a maintained streaming authenticated-encryption format with a versioned application manifest; exact crypto crate selection is locked during implementation after supply-chain and interoperability verification.
