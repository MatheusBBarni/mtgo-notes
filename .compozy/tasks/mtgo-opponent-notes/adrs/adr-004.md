# ADR-004: Build the Windows Companion on Tauri 2

## Status

Accepted

## Date

2026-07-28

## Context

The repository is greenfield. V1 needs a Windows-only desktop process that owns encrypted local data, global shortcuts, a system tray, automatic context detection, and an always-on-top overlay that never takes gameplay focus automatically. The UI must implement the dense desktop adaptation of `DESIGN.md`, while sensitive disclosure and persistence decisions must remain outside disposable webview state.

The user considered Tauri and Electrobun and selected Tauri after reviewing their current Windows, SQLite, window, shortcut, and permission models.

## Decision

Build V1 with Tauri 2, a React 19 and TypeScript frontend, and a Rust host.

- The Rust host owns the encounter state machine, disclosure policy, provider adapters, SQLCipher repository, background jobs, global shortcut, tray lifecycle, backup/restore, export, updater, and window commands.
- React renders three least-privilege webviews: `main`, `overlay`, and `capture`. The overlay receives only a policy-filtered view model. The capture window receives only the active encounter identifier and draft state.
- Closing `main` hides it and leaves the tray process, detector, shortcut, and overlay service active. The tray exposes Open, Show/Hide Overlay, Pause Detection, and Exit. Launch with Windows is opt-in.
- V1 supports Windows 10 22H2 and Windows 11 on x64. The installer bootstraps a minimum WebView2 runtime when needed. Native ARM64 is deferred.
- Application updates use signed Tauri updater artifacts. Update checks at launch are opt-in and disclosed; downloads and installation always require confirmation.
- Rust commands return typed plain-data envelopes. Tauri capabilities grant each window only the commands it needs; webviews never receive direct filesystem, SQL, updater, provider, or shell access.

## Alternatives Considered

### Alternative 1: Electrobun with React and TypeScript

- **Description**: Use Bun as the native host and typed TypeScript RPC throughout.
- **Pros**: One primary language, direct typed RPC, simple window and shortcut APIs.
- **Cons**: Less mature least-privilege capability controls and no equally mature official encrypted-SQLite path for this design.
- **Why rejected**: The Rust boundary and Tauri capabilities better isolate disclosure, keys, native detection, and destructive data operations.

### Alternative 2: Native C# and WPF

- **Description**: Build the entire companion with .NET and WPF.
- **Pros**: First-class Windows UI Automation, OCR, window, and accessibility integration.
- **Cons**: Discards the selected Tauri/Electrobun direction and makes reuse of the requested token-driven web UI less direct.
- **Why rejected**: Tauri retains native Windows access through Rust while matching the desired frontend workflow.

### Alternative 3: One Webview with Conditional Overlay UI

- **Description**: Reuse the main webview as the overlay and capture surface.
- **Pros**: Fewer windows and IPC surfaces.
- **Cons**: Couples focus and visibility lifecycles and makes stale historical disclosure more likely.
- **Why rejected**: Separate capability-scoped windows make focus behavior and fail-closed rendering independently testable.

## Consequences

### Positive

- Native Windows integrations and encryption keys stay in one trusted Rust process.
- Webview permissions can be minimized by window.
- The overlay and rapid-capture surface can recover independently of the main window.
- Tauri's signed updater and WebView2 bootstrap cover the selected release model.

### Negative

- The implementation spans Rust and TypeScript.
- SQLCipher requires a Rust-owned repository rather than Tauri's generic SQL plugin.
- Windows-only native code needs dedicated CI and packaged-app testing.

### Risks

- **Focus stealing**: Exercise packaged focus tests against MTGO and fail by leaving the overlay hidden.
- **Capability drift**: Snapshot capability manifests and reject broad wildcard permissions in CI.
- **WebView2 differences**: Test the minimum supported runtime and current Evergreen runtime.

## Implementation Notes

Use a workspace with `src/` for React, `src-tauri/src/` for the host, and `src-tauri/capabilities/` for per-window grants. Bundle Inter Variable as the primary UI font with `Segoe UI` and `system-ui` fallbacks. Apply the `DESIGN.md` palette, 4 px spacing scale, 6/10/12 px radii, hairline borders, scarce shadows, and visible blue focus rings; do not reproduce the reference site's marketing navigation or loose section rhythm.
